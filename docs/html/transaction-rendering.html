Compute rows from the complete track

The track index sorts compact transaction identities and lifetimes by start time, then transaction ID. It assigns the lowest available row using two heaps: one tracks active end times and the other tracks reusable row numbers. Start-time ordering does not assume transaction IDs or completion times are monotonic.

Each stream and each individually displayed generator has its own immutable index. A packet can therefore occupy row 3 in its stream and row 0 when its generator is displayed alone. Drawing commands include the displayed track identity, so the two views cannot overwrite one another’s geometry. Panning keeps those row assignments and the total track height stable. Sparse windows may consequently contain empty rows that are occupied elsewhere in the recording.

Recording-owned geometry

Complete-track lifetimes and row indexes survive viewport changes. VTR builds them on a worker when a stream is requested; FTR reuses its loaded stream data to build indexes on first access.

Tile-owned drawing

The time window, pixel width and vertical scroll position select samples from visible rows. Resize, pan, or scroll invalidates positions, not complete-track row assignments.

Requested payloads

VTR requests rich details only for visible individual transactions and inspector selection. Geometry remains drawable while those payloads arrive asynchronously.

Query occupied screen columns

Within each row, transactions do not overlap, so both start and end times are ordered. A binary search finds the first interval overlapping the window, including a long interval that started earlier. The query then jumps to the next occupied screen column rather than visiting every transaction between the viewport edges. Offscreen rows are omitted before constructing drawing commands.

Several transactions starting in the same screen column become a dense sample with their count and combined extent. The last member preserves a long interval that extends beyond the dense column. Hover explains the aggregation; clicking selects that final member. Zoom in to resolve individual intervals and their event dots. Aggregates omit event dots rather than showing a representative’s events as though they described the entire group.

Keyboard navigation also uses the complete indexes. It moves chronologically by start time and identity across displayed tracks, without collecting every transaction ID or requiring the next transaction’s payload to already be loaded.

Bin arithmetic uses integer timestamps, including large nonzero origins. Per visible row, a query performs at most one initial search and one jump per occupied column. Output is bounded by visible rows × pixel columns. Individual transactions and event attributes remain separate from this visual summary.

What is bounded, and what still costs time

Rendering queries are screen-bounded after index construction. Building geometry is linear in storage and includes sorting; it requires visiting the complete requested stream. The reference VTR reader temporarily retains decoded blocks during that initial scan and releases them afterward. This is not a bounded-memory index builder. Legacy FTR still loads rich stream data through its parser. Large individual event lists are also decoded as part of their transaction payload.

A manual timing regression creates one million real in-memory transactions and compares the previous per-frame row-packing function with an indexed 1920-column query, best of three in the same process. On arm64 with Rust 1.96.0, using the repository’s debug profile:

OperationMeasured time
One-time geometry construction91.1 ms
Previous per-frame row packing alone573.5 ms
Indexed screen query, 1920 samples1.6 ms

These are query-preparation timings, not file-open, payload-decode, or end-to-end paint timings. Run the ignored transaction_index_render_benchmark library test with --ignored --nocapture to repeat them. A separate virtual billion-element-row test exercises the identical query routine, verifies that counts sum to one billion, and checks that metadata accesses are bounded by the number of screen columns and binary-search depth. It does not allocate or load a billion-record file.

Regression tests cover unordered IDs, nonmonotonic completion times, stable rows across windows, separate stream/generator geometry, long intervals spanning the viewport, clipping, and explicit screen-selected payloads. The CHI snapshot shows the 64-packet burst in two controller streams; it uses compact row spacing and a taller canvas to include both complete tracks.
