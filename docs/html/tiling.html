01 / THE SEPARATION

A tile is a view with an identity.

Imagine following a bus transfer. You want an overview on the left and a close-up of the handshake on the right. Both should show the same signal list, but zooming into the close-up should leave the overview alone. Moving the time cursor, on the other hand, should update the shared point of inspection.

Surfer models those choices separately. The layout says where a tile is. The tile says how it looks at content. A resource says what content it shares. The simulation document supplies data to all of them.

Where

Layout

Splits, tab groups, active tabs, and focus. A leaf names a TileId; it does not contain a waveform or own a signal list.

How

Tile

A stable identity, an optional title, and a concrete kind. A waveform kind owns one viewport and its presentation settings.

What

Shared content

An ItemListId names a reusable list of displayed items. Two waveform tiles can reference that same list without sharing their time windows.

Identity survives rearrangement. Moving a pane changes the layout, not its application identity. TileId and ItemListId are distinct types; neither is an egui layout-node ID.

Grounded in tiles/mod.rslayout.rswaveform.rs

“Tile-local” does not mean “all selection is local.” A waveform’s focused item and focused transaction live in its view. Item selection lives in the shared list. Changing a shared list must also repair any surviving views whose references became invalid.

03 / LINKED OR INDEPENDENT

Share the list. Keep the viewpoint.

A linked split creates a new waveform tile with a new identity and the same list reference. An independent split copies list content into a fresh resource and rewrites the new tile’s reference. Neither duplicates the loaded simulation document.

Linked content does not automatically imply linked scrolling. Vertical synchronization is an explicit setting for views of the same list; horizontal navigation remains per view. The experiment isolates content, viewport, and cursor ownership rather than simulating vertical scrolling.

Copy a dependency graph, not a special-case list.

A kind declares Dependencies: a set of typed resource references plus an “opaque” flag. Today the resource enum has one variant, ResourceId::ItemList, but the set can contain several lists. Independent copying duplicates each distinct dependency once, remaps every reference in the detached copy, and checks that the resulting dependency set is exactly the copied set. A partial remap cannot enter the workspace.

04 / THE LAYOUT TREE

Geometry is a projection of structure.

The persistent tree has three node forms: Tile, Tabs, and Split. Splits carry an axis, relative shares, and children. Tabs carry an active index and only tile leaves. The adapter translates that contract into egui’s runtime tree.

This explorer uses equal split shares and stable IDs. It demonstrates active tabs and topology, not the drag-and-drop implementation.

Validate before committing.

A layout must contain exactly the workspace’s tiles, once each. Active indices must exist; split shares must match child counts and be finite and positive. Bounded depth and node counts prevent oversized trees.

Adapter edits carry the layout revision they were based on. A stale proposal is rejected, as is one that could resurrect a closed tile. Visible-pane geometry is revision-checked too.

The adapter is disposable.

The egui tree may use tab wrappers to render chrome. Those runtime details do not redefine persistent ownership. A pane-edge drop splits the destination tab group; a tab drop onto a split joins its nearest visible pane.

Invalid runtime trees are rebuilt from validated state. Submitted proposals are reconciled on the next frame, including ignored or rejected proposals.

With one tile, Surfer hides the tab bar and focus outline by default. Setting layout.hide_single_tab_bar = false exposes those controls. A compact presentation still uses the same tile architecture.

05 / INTENT TO MUTATION

Capture the target before focus moves.

“The focused tile” is an input-time intention, not a safe address for a queued action. A click, keyboard shortcut, or palette command resolves its target to a concrete TileId before dispatch. Otherwise a later focus change could send the action to the wrong pane.

Based on the focus-change regression test in tiles/view.rs. Playback is optional; every step is available manually.

Tile scope

ToTile(TileId, TileMessage)

Kind-specific settings and navigation. A list-edit message reaches content through the target tile’s validated resource reference.

Document scope

ToDocument(DocumentCommand)

Shared cursor and active-scope changes. These operations do not need a waveform list or viewport.

Workspace scope

Workspace(WorkspaceCommand)

Create, split, move, close, rename, and focus. The workspace maintains membership and resource integrity.

A split is prepared before it becomes visible.

  1. Describe the change. Capture the source tile, split direction, and supported copy mode.
  2. Prepare a detached candidate. Clone the kind’s semantic state, allocate a new tile identity, and stage any copied resources.
  3. Check the whole insertion. Validate placement, singleton rules, IDs, dependencies, and references into resource content.
  4. Install the complete result. Commit only after the candidate is valid. An error leaves live storage and the layout revision unchanged.

Allocation is intentionally monotonic: an identity consumed while staging a failed operation is not recycled. Atomic live-state mutation does not mean rolling back session counters.

06 / TIME & PERSISTENCE

Restore meaning. Rebuild machinery.

Closing, undoing, loading, and completing background work all cross time boundaries. They need different rules. Saved state restores a workspace’s meaning; undo restores an affected semantic change; neither should revive obsolete runtime work.

Resource lifetime

Last owner closes.

If A and B share list 7, closing A keeps list 7 alive. Closing the last known owner permits collection. Dependency declarations drive this decision—not a waveform-specific convenience accessor.

Semantic history retains resources absent from the live workspace. Undo validates membership and dependencies before restoring them, resets restored caches, and preserves resource identities and navigation of surviving linked views.

History is selective

Undo the edit.

History records affected items, resources, moves, layouts, titles, markers, and settings. It is not a snapshot of the whole application.

Viewport navigation is excluded from content history. Split shares and active tabs are navigation rather than topology. Runtime allocators and request epochs never travel backward with undo.

The saved envelope is intentionally small.

This envelope covers the workspace; the surrounding user state also carries document settings. It is not an embedded trace dump. Waveform payloads save list references, navigation, and column settings. Geometry, drawing caches, egui node IDs, and request tokens are not saved. A complete replacement is validated before IDs are installed and the workspace epoch advances.

An unknown tile is preserved, not guessed. An unrecognized kind or unsupported payload version retains raw RON, including enum names. Its dependencies are opaque, so all stored resources are conservatively retained while it survives. Known missing dependencies remain errors. Independent copying is unsafe because unknown references cannot be remapped; current unknown tiles do not support splitting.

A malformed payload for a recognized kind/version is a load error, not an unknown placeholder. Unsupported workspace versions are rejected. Version-zero migration is a separate path: the old shared waveform content becomes an item list, and its old viewports become linked waveform tiles.

A late answer must still belong to the present.

WorkspaceRuntime supplies a request-token contract for tile-owned asynchronous work. Its acceptance helper checks epochs and the pending token; the consumer must additionally check that the owner exists and the full input key still matches. This is extension infrastructure and a tested contract, not a claim that every existing background task is wired through it.

07 / A DEBUG PLATFORM

The window system is the foundation.
The connections make it a debugger.

Here, “Verdi-like” is a product direction: a coordinated environment for investigating hardware through waveforms, source, hierarchy, relationships, and domain-specific views. Tiling provides a place for those tools to coexist. It does not, by itself, provide the design database or cross-view semantics they need.

The registry is a concrete Rust enum and a descriptor table. Adding a built-in kind extends that registry and its rendering, messages, codecs, and resource contracts. This is not a dynamically loaded tile-plugin interface. There are already WCP action types for declaration, drivers, and loads; those integration hooks do not amount to a built-in RTL source or schematic tile.

VTR and VDB remain separate. A reliable join needs matching design/build identity and explicit mappings to traced objects; matching display names alone is insufficient.

Reuse the boundaries.

A source tile can keep its scroll position locally. A driver graph can declare shared query-result resources. New kinds can use targeted messages, versioned payloads, and semantic history without teaching the layout what a driver or a source file is.

The dependency set already supports several references per owner. Add a new ResourceId variant and concrete storage/copy operations when a real new resource type exists.

Design the missing contracts.

Cross-probing needs typed selection events, explicit recipients or link groups, and an origin to prevent feedback loops. Decide which actions merely highlight and which navigate. A focused pane should not silently become the destination of an old query.

A multi-document comparison needs document identities and time-domain mapping; the current shared WaveData is not a multi-document debug session model. Async consumers must adopt the request contract, not merely allocate tokens.

A practical extension checklist

  1. Give the kind a narrow responsibility. Specify what it reads, what it owns locally, and what it shares. Define empty, unavailable, and stale-source states.
  2. Register a versioned semantic payload. Decide multiplicity and split behavior. Keep caches and pending work out of persistence and define how old versions migrate.
  3. Declare and validate every resource reference. Include references into resource contents and total remapping for independent copies. Define what survives close and undo.
  4. Connect it through explicit messages. Capture targets, establish any cross-view linking policy, and invalidate background work when its owner or inputs change.
  5. Prove its lifecycle and explain it. Exercise create, move, close, undo, save/load, unavailable data, and late completion. Add the feature’s interactive HTML chapter.
The durable idea: new debug tools should add new kinds of knowledge, not new ways to accidentally own the same state. Stable identities, declared dependencies, and explicit mutation boundaries make that possible.

Check your mental model.

Two linked waveforms show different time ranges. Is that inconsistent?

No. Their list identity is shared, but each waveform owns a viewport. Linked content and horizontal navigation are separate choices.

Can closing a tile always free the list it references?

No. Another tile may still reference it. An opaque unknown kind may require conservative retention of all resources, and semantic history may retain a removed resource for undo.

Does undo make an old background result valid again?

No. Restored semantic state does not restore pending runtime work. Request consumers must verify current ownership, epochs, the pending token, and the complete input key.

Does adding a source tile complete an integrated RTL debugger?

No. It supplies a view. Reliable cross-probing also needs design data, trace-to-design mappings, typed coordination, explicit linking policies, and lifecycle-safe queries.
